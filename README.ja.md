# Transom

**Macの各ウィンドウのすぐ上に、Windows風のウィンドウボタンとアプリメニューを。**

Transomは、macOSの通常ウィンドウの上に独立したタイトルバーを追加するメニューバー常駐アプリです。各ウィンドウの近くでアプリメニュー・最小化・最大化・閉じるを操作できます。Mac本来のメニューバー、ウィンドウボタン、ツールバーもそのまま使えます。バーにはアプリ名とメニューを表示し、ウィンドウタイトルはツールチップに表示します。

名前のTransomは、ドアや窓の上に付ける小窓（欄間）に由来します。

**開発プレビュー版・0.1.0-dev・MITライセンス。** 下記の手順でソースからビルドできます。対応状況はアプリやmacOSのバージョンによって異なり、Apple公証済みのリリースはありません。大切な作業で使う前に[検証状況](#検証状況)を確認してください。

## 主な機能

- **ウィンドウの近くでメニュー操作。** アプリメニューや「ファイル」「編集」などをmacOS標準のメニューで表示します。幅が足りない場合は `»` にまとめます。
- **右端のウィンドウボタン。** 最小化、最大化／復元、閉じるを操作できます。最大化はネイティブフルスクリーンへ移行せず、外付けバーの高さを空けて配置します。
- **ドラッグとダブルクリック。** バーの空き部分をドラッグして移動、ダブルクリックで最大化／復元。空き部分の上端5ポイントをダブルクリックすると、横位置と幅を保って縦方向だけ最大化／復元します。
- **右クリックメニュー。** ウィンドウ操作、その窓の上に空間を確保する操作、アプリの除外を選べます。
- **外観の設定。** **TR** メニューから、バーの色、アクティブ時の色、ライン／塗りつぶし、ラインの太さ、バーの高さを変更できます。
- **アプリ別の除外と任意のログイン起動。** どちらも **TR** メニューから設定できます。本体UIは日本語・英語に対応し、macOSの言語設定に従います。

## 動作・ビルド環境

| 項目 | 条件 |
| --- | --- |
| macOS | ビルド設定上はmacOS 14以降。実機記録はmacOS 26と27.0.1の個別シナリオで、対象OSすべてを検証したものではありません。 |
| ハードウェア | 実機検証はApple Siliconで実施。Intel Macは未検証です。 |
| ビルドツール | Xcodeまたは対応するCommand Line ToolsのSwift 6ツールチェーン。Swift 5言語モードを使います。 |
| 権限 | ビルドした `Transom.app` へのアクセシビリティ許可。 |

外部Swiftパッケージへの依存はありません。HomebrewやXcodeGenも不要です。

## ビルドと起動

リポジトリをcloneするか、ソースのZIPをダウンロードして展開します。ターミナルで実行してください。

```bash
git clone https://github.com/digimaga/Transom.git
cd Transom
bash scripts/build-app.sh --release
open dist/Transom.app
```

ZIPの場合は、展開した `Transom` フォルダでターミナルを開き、ビルドコマンドから実行します。

1. macOSのメニューバーに **TR** が表示されます。
2. **システム設定 → プライバシーとセキュリティ → アクセシビリティ** で **Transom** を許可してください。バーが出ない場合はTransomを再起動します。
3. 通常ウィンドウを下へ動かし、メニューバーの下に40ポイント程度の空間を作って試してください。外付けバーの標準の高さは30ポイントで、窓の上に空間が必要です。

**TR → 最前面の1枚にバー用の空間を確保** でも空間を作れます。この明示操作は対象の1枚だけを移動し、必要なら縮小します。起動時に窓を自動で並べ替えることはありません。ドラッグ・最大化・復元を操作した場合も、対象の位置やサイズが変わります。

ビルド先は `dist/Transom.app` です。`/Applications` へのインストールやログイン起動の有効化は行いません。起動場所は固定してください。移動や再ビルドをした場合は、実際に起動するアプリにアクセシビリティ許可があるか確認します。

### 署名と更新

ビルドスクリプトは、キーチェーンに `Transom` という名前の証明書があれば使用し、なければアドホック署名を行います。Appleの公証は行いません。署名鍵・証明書は同梱していません。署名IDを指定する場合は `CODESIGN_IDENTITY` を設定します（`-` はアドホック署名）。

アプリの差し替え・再ビルド前に **TR** メニューからTransomを終了してください。署名が変わるとアクセシビリティ許可の再登録が必要な場合があります。利用をやめる場合はアプリを終了します。「ログイン時に起動」を有効にした場合は先に解除してください。

## 権限とプライバシー

アクセシビリティ許可により、Transomは他のアプリの窓・メニュー情報を読み、利用者が選んだ操作を実行できます。保存や閉じるも対象アプリが処理するため、そのアプリのデータに変更が生じる場合があります。

- 窓のタイトル、取得可能な文書URL、メニューラベル、選択状態などをメモリー上で利用し、操作先を特定・照合します。窓のタイトルはバーのツールチップに表示される場合があります。
- アプリのネットワーク通信やアクセス解析はありません。画面録画・入力監視の権限要求、キー入力の記録、SIPの無効化、他アプリへのコード注入も行いません。
- 外観、有効／無効、除外するアプリの識別子はmacOSの設定領域へローカル保存します。実行時ログには状態、数値のウィンドウID、処理時間を記録しますが、文書名・文書URL・メニューラベル・選択文字列は含めません。
- **TR → 診断情報をコピー（文書名を含まない）** は、バージョン、OS、権限・機能の状態、窓数などをクリップボードにコピーします。自動送信はしません。共有前に内容を確認してください。

## 現在の制限

- ネイティブフルスクリーン、シート、モーダルダイアログ、幅280ポイント未満または高さ120ポイント未満の窓は対象外です。
- 上下方向にバーの空間が足りない場合は、元の操作部や本文を覆わず非表示になります。窓が左右や下へはみ出す場合はバーも追従し、画面外の部分が切れて見えます。複数ディスプレイでの動作は実機検証が必要です。
- メニューは各アプリがアクセシビリティ経由で公開する範囲に限られます。遅延生成されるメニュー、独自UI、Optionキーによる切替項目は利用できない場合があります。その場合はMac本来のメニューを使ってください。
- 正確な窓・フォーカス・メニューの文脈を照合できない場合、操作を拒否します。タイトルによる推定や、結果不明のコマンドの自動再試行は行いません。
- Spacesでは現在見えている窓に合わせてバーを表示します。バーは別ウィンドウなので、Mission Control・Stage Manager・Space切替のアニメーションが完全に一体化する保証はありません。
- 正確なウィンドウIDの取得には、`TransomBridge` 内でmacOSの非公開APIを使います。OS更新で互換性が失われる可能性があります。Mac App Store向けの構成ではありません。
- 最大化／復元は対象アプリのサイズ制約に影響されます。復元先の枠はTransomの実行中、その窓を追跡している間だけ保持します。

## 困ったとき

| 症状 | 最初に確認すること |
| --- | --- |
| バーが出ない | 起動中のアプリへのアクセシビリティ許可、TRの有効設定、アプリの除外設定、通常窓の上の空間を確認します。 |
| メニューが欠ける・操作を拒否される | Mac本来のメニューを試します。Transomの診断情報と、テスト文書での最小限の再現手順を集めてください。 |
| 再ビルド後に許可が効かない | 旧版を終了し、現在のアプリの場所とアクセシビリティ登録を確認して、そのコピーを起動し直します。 |
| ビルドできない | `xcrun swift --version` がSwift 6以降で、選択中のXcode／Command Line Toolsを利用できることを確認します。報告には最初のビルドエラーを添えてください。 |

報告方法は[開発参加・不具合報告](CONTRIBUTING.md#日本語)を参照してください。ログやスクリーンショットを投稿する前に個人情報を取り除いてください。

## 検証状況

## 開発

```bash
# 両アプリのビルド、共通ロジックのテスト、ソース・構成チェック
bash scripts/verify.sh

# 窓・メニューの手動検証用アプリをビルド
bash scripts/build-app.sh --lab
open dist/TransomLab.app
```

TransomLabはテスト用の窓を作ります。「検証保存」を実行すると `~/Library/Application Support/TransomLab/` にテストデータとイベントログを書き込みます。別アプリであり、通常のTransomバンドルには含まれません。

CIのビルドや単体テストでは、実際のアクセシビリティ操作・フォーカス・Spacesを検証できません。実機では[受入チェックリスト](docs/ACCEPTANCE.md)を使い、新しく確認した結果と過去の記録を区別してください。
